# Кейс №3. Взлом сервера баз данных Linux и создание бэкдор-пользователя

## Вводные данные
- **Сервер:** Сервер баз данных Linux (`10.20.40.12`)
- **Источник:** Журнал `/var/log/auth.log`

## Хронология событий
1. **09:05–09:06 (Штатная работа):** Администратор `adm_petrov` вошёл по SSH с внутреннего IP `10.20.1.5` и через `sudo` перезапустил службу базы данных (`postgresql`).
2. **11:42 (Брутфорс SSH):** С внешнего IP `194.26.135.88` по порту `22` (`sshd`) зафиксированы неудачные попытки входа (`Failed password`) и последующий успешный вход (`Accepted password`) под учёткой `adm_petrov`.
3. **11:43:01 (Закрепление):** Выполнена команда `/usr/sbin/useradd backdoor_user` — злоумышленник создал запасную учётную запись для сохранения доступа к серверу.

## Полезные команды проверки
- `grep "sudo" /var/log/auth.log` — найти все команды, запущенные с правами администратора.
- `grep "194.26.135.88" /var/log/auth.log` — найти все действия с атакующего IP.

## Вердикт и действия аналитика (SOC L1)
- **Вердикт:** `True Positive` (компрометация сервера и создание бэкдора).
- **Действия:**
  1. Изолировать сервер `10.20.40.12` от сети.
  2. Заблокировать внешний IP `194.26.135.88` на межсетевом экране.
  3. Удалить созданную учётную запись `backdoor_user`.
  4. Сменить пароль и отозвать ключи у `adm_petrov`, передать инцидент на L2.
